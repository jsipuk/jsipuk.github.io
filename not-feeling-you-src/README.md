# What to do when you're not feeling you

> Tell us how much time, money and energy you have, and we'll give you three things you could actually do.

A small recommendation site for days when you feel a bit off. Six quick questions (budget, time, company, energy, what would help, in or out), then exactly three ideas:

1. **The obvious one**: the best fit.
2. **Something different**: a credible alternative from a different category.
3. **Wildcard**: still fits your budget, time, company and energy, but you weren't thinking of it.

It isn't therapy, a wellbeing programme or a productivity tool. There are no accounts, no database and no AI in V1.

## Local setup

Needs Node 20+.

```bash
npm install
npm run dev          # http://localhost:3000
```

## Tests

```bash
npm test             # Vitest: engine unit tests, 25 recommendation scenarios, and a check that every idea can be a result
npm run sweep        # Optional, ~2 min: every answer combination; reports unreachable and over-shown ideas
npm run awkward      # Optional: prints results for 30 deliberately awkward answer sets to read and rate by hand
npm run typecheck

npm run build        # static export to out/
npm run test:e2e     # Playwright core flow, mobile (390px) and desktop, against out/
```

Playwright needs a Chromium. If `npx playwright install` isn't an option, point it at one:
`PW_CHROMIUM=/path/to/chrome npm run test:e2e`.

## Build and deploy

The app is a fully static export (`output: "export"`): no server, no API routes, no external services.

- **Vercel**: import the repo, set the root directory to `not-feeling-you-src`, keep the defaults. Nothing else to configure.
- **jsip.uk (GitHub Pages)**: `npm run build:pages` builds with `NEXT_PUBLIC_BASE_PATH=/not-feeling-you` and copies the output to `../not-feeling-you/`. Commit that folder; it goes live when it lands on `main`.
- **Anywhere else**: `npm run build` and upload `out/`.

## How recommendations work

All in `lib/`. Deterministic: the same answers always give the same three results. No LLM decides anything. Equal scores break on a hash of the answers, so different answers rotate through equally good ideas rather than the lowest ID always winning.

### 1. Hard filters (`filters.ts`)

An activity is dropped if:

- its **minimum** cost is over the budget,
- its **minimum** time is over the time available,
- it doesn't suit the company (solo, partner, friends, family),
- you said "Stay home" and it can't be done at home, or "Get me out" and it's home-only,
- the energy gap is extreme (e.g. "Basically none" vs go-karting).

Energy is otherwise scored, not filtered. Booking isn't filtered.

### 2. Score (`score.ts`)

| Signal | Points |
| --- | --- |
| First feeling matches (dominant / supporting) | 30 / 22 |
| Second feeling matches | 15 / 11 |
| Energy: exact / one level off / two off | 20 / 10 / 2 |
| Time: typical fits with room / just fits / only the minimum fits | 15 / 10 / 4 |
| Company supported | 12 |
| Setting: works where you asked / user said "Either" | 10 / 8 |
| Action preference: main action / secondary action | 8 / 5 |
| Budget: typical cost within budget / only minimum within | 5 / 2 |
| Tie-breakers: typical time uses 30–100% of what you have (+3, or +1 from 15%); your energy is the idea's main level (+2) | 0–5 |

Budget is a ceiling, not a target, so a free idea never loses points because you said £50.

Two feelings in the data can't be picked on screen: **calm** counts as a partial match for "Comfort me", and **perspective** for "Get me outside".

**Surprise me** drops the feeling points and adds novelty instead: +15 if the idea is new to most people, plus up to 20 from its wildcard score.

### 3. Diversity (`diversify.ts`, `recommend.ts`)

The top score becomes **The obvious one**. The next two slots are chosen after penalising similarity to what's already picked:

- same category: −20 (and a repeat category is only used if nothing else fits)
- same main action: −8
- same dominant feeling: −5
- same setting and environment pattern: −5

Every card has to speak to at least one feeling you picked; the engine only falls back to off-brief ideas when nothing else fits.

The **wildcard** is ranked by half its fit score plus half its `wildcardScore`, with +10 for a quirky, silly or adventurous personality and +8 for novelty. It must still score at least 70% of the top result and sit within one energy level of the user, so it's odd but never implausible.

### 4. Nah

"Nah" replaces one card only. It picks the next best for that slot, avoids anything already shown, and keeps the other two cards untouched. Rejected IDs are kept in `sessionStorage` for that set of answers.

## Activity data

`data/activities.json` holds 192 activities, generated by `scripts/build_activities.py`. 120 came from the original inventory spreadsheet (`data/source/v1-inventory.xlsx`) and 81 more (`WTY121`–`WTY201`) were written to fill gaps found by sweeping every answer combination and by rating awkward answer sets by hand. Nine near-duplicate cosy buys were then folded into five grouped ideas (e.g. socks, slippers, pyjamas and dressing gown became “Buy something soft to wear at home”). Each group keeps one original ID and lists the rest in `mergedFrom`, so saved items using an old ID still resolve. The script also splits the sheet's broader categories (e.g. Comfort into Cosy kit, Sleep and Scent) so the diversity step doesn't hide most of a category behind one winner.

```bash
pip install openpyxl
npm run data
```

The spreadsheet supplies IDs, titles, categories, cost and time ranges. The script adds, per row: fixed enums for energy, company, setting, environment, actions, feelings and personality; typical cost and time; planning (`now`, `same-day`, `booking`); `wildcardScore` (0–100); `whyItWorks`; and `makeItBetter`. Where a title or summary needed rewriting it's done in that script so the change is reviewable.

Each activity keeps its source: `reddit` (with the AskUK thread URL) for ideas from the original thread, `original` for expansions. The UI never shows this. No Reddit comment is copied verbatim.

One field is added beyond the original schema: `category`, which the diversity step needs.

To add an idea: either add a spreadsheet row plus a matching entry in the `A` dict, or add a complete entry to `EXTRAS`. Then run `npm run data` and `npm test`.

## Typography

Two families, one rule. Fraunces is used for headings only: the page title, each question, and idea titles. Everything else, including the wordmark, labels, buttons and body text, is IBM Plex Sans.

## Saved ideas

`localStorage` only (`nfy:saved`). No account, nothing leaves the browser.

## Not in V1 (roadmap)

- weather-aware ideas
- opening hours, local museums, parks, markets and attractions
- nearby events and travel-time filtering
- child-age suitability and accessibility needs
- repeat avoidance, likes and dislikes, favourites
- seasonal ideas
- affiliate links, only if genuinely useful
- an optional AI layer that rewrites wording (never one that decides what's suitable)
